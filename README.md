# Эмулятор оболочки — вариант 14, этапы 1–3

Участник: Михайлова Анна Михайловна.

Учебный эмулятор UNIX-подобной оболочки на Python с окном Tkinter.
Реализованы только первые три этапа. Команды ОС не запускаются.
`ls` и `cd` пока являются заглушками: печатают имя и аргументы.

## Запуск на macOS/Linux

Нужен Python 3.12 или новее с Tkinter. Сторонние библиотеки не нужны,
сборка не требуется. Выполняйте команды из корня проекта.

Проверка Python: `python3 --version`.
Проверка Tkinter: `python3 -m tkinter` — открывается тестовое окно.

```sh
python3 -m src.fixtures
sh run.sh --vfs .generated/deep
```

Первой командой создаются учебные источники VFS, второй открывается
эмулятор. Без учебных файлов: `sh run.sh`.

Тесты:

```sh
python3 -m unittest discover -s tests -v
```

Стартовый скрипт без окна:

```sh
sh run.sh --vfs .generated/deep --script examples/stage3.txt --batch
```

Этот пример включает `vfs-init`: учебная папка `.generated/deep`
очищается. Для восстановления повторите `python3 -m src.fixtures`.

## Запуск на Windows

Нужен Python 3.12 или новее с Tkinter. Из корня проекта:

```bat
python -m src.fixtures
run.bat --vfs .generated/deep
python -m unittest discover -s tests -v
```

`requirements.txt` содержит только указание версии Python.
Сторонние библиотеки устанавливать не требуется.

## Этап 1: окно и REPL

REPL — цикл чтения команды, выполнения и вывода результата.
Заголовок окна: `Эмулятор - [username@hostname]`.
Имя пользователя и компьютера берутся из реальной ОС.
Ввод разделяется по пробелам; кавычки не объединяют слова.
Неизвестная команда и неверные аргументы показывают `error:`.

| Команда | Поведение на этапах 1–3 |
|---|---|
| `ls [аргументы]` | Выводит своё имя и список аргументов |
| `cd [path]` | Выводит своё имя и аргумент; больше одного аргумента — ошибка |
| `exit` | Завершает сеанс; аргументы не принимаются |

`cd` пока не меняет текущий каталог; `ls` не показывает содержимое VFS.
Настоящая навигация относится к следующему этапу задания.

## Этап 2: настройки и стартовый скрипт

- `--vfs PATH` — физическая папка источника VFS.
- `--script PATH` — файл UTF-8 с командами эмулятора.
- `--batch` — выполнение без интерактивного окна.
- `--help` — справка по параметрам.

Пути относительны рабочему каталогу процесса.
При запуске показываются все итоговые параметры.
Стартовый скрипт показывает ввод и вывод каждой команды.
Комментарии начинаются с `#` вне кавычек, включая комментарии
после команды. Ошибка показывает номер строки; следующие команды
продолжают выполняться. `exit` прекращает скрипт.
Коды процесса: 0 — успех, 1 — ошибка загрузки или скрипта,
2 — неверные параметры командной строки.

## Этап 3: VFS

Источник — каталог на диске. Структура и байты файлов считываются
в память. Работа с загруженной копией не меняет исходную папку,
кроме отдельно предусмотренной служебной команды `vfs-init`.
Символические ссылки, junction и специальные файлы отвергаются.
Без `--vfs` создаётся пустой корень `/`.

| Команда | Назначение |
|---|---|
| `vfs-info` | Имя VFS и SHA-256 её данных и виртуальных метаданных |
| `vfs-init` | Очистка физического источника и сброс VFS до пустого корня |

`vfs-init` применяется к учебным папкам `.generated/`.
Программа отвергает корень диска, домашнюю папку, текущую папку
проекта и её предков, а также пути через ссылки.

Генератор `python3 -m src.fixtures` создаёт три источника:
`minimal` — пустой, `files` — несколько файлов,
`deep` — файлы и папки не менее чем на трёх уровнях.
Учебные данные и кеши исключены из Git через `.gitignore`.
Хеш SHA-256 вычисляется по отсортированным путям, типам узлов,
виртуальным правам, владельцам, группам и байтам файлов.
Формат описан в [docs/VFS.md](docs/VFS.md).

## Пример ручной демонстрации

После запуска с `.generated/deep` введите в окне:

```text
ls
ls /docs
cd /docs
cd a b
unknown
vfs-info
vfs-info extra
vfs-init
vfs-info
exit
```

`ls` и `cd` показывают аргументы. `cd a b`, `unknown` и
`vfs-info extra` выдают ошибки; окно остаётся открытым.
`vfs-info` показывает имя и хеш. После сброса хеш меняется.
`exit` закрывает окно.

Сценарии для macOS/Linux:

```sh
sh scripts/stage2.sh
sh scripts/stage3.sh
```

Они проверяют успешные и ошибочные режимы запуска и три структуры VFS.
В исходном теге этапа 2 путь VFS только сохранялся в настройках;
в текущей версии этапа 3 физический источник должен существовать.

## Структура проекта и функции

- `src/main.py` — запуск и создание сеанса.
- `src/interface.py` — окно, ввод и вывод.
- `src/shell.py` — заглушки, выполнение команды и ошибки.
- `src/parsing.py` — разделение команды по пробелам.
- `src/config.py` — параметры командной строки.
- `src/startup.py` — чтение стартового скрипта и комментарии.
- `src/vfs.py`, `src/loaders.py` — данные в памяти и загрузка папки.
- `src/services.py` — `vfs-info`, `vfs-init`.
- `src/fixtures.py` — создание учебных источников VFS.
- `src/settings.py` — настройки варианта 14 для этапов 1–3.
- `tests/` — автоматические проверки.
- `examples/` — успешные и ошибочные стартовые скрипты.
- `scripts/` — демонстрационные сценарии реальной ОС.
