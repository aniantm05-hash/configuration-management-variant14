# Эмулятор оболочки. Вариант 14

Эмулятор UNIX-подобной оболочки на Python с графическим окном Tkinter.
Реализованы этапы 1-4. Команды работают с VFS в памяти.
Команды реальной ОС из эмулятора не запускаются.

## Запуск

Нужен Python 3.12 или новее с Tkinter. Сторонние библиотеки и сборка
не требуются. Все команды запуска выполняются из корня проекта.

На macOS/Linux:

```sh
python3 --version
python3 -m tkinter
python3 -m src.fixtures
python3 -m src.main --vfs .generated/deep
```

Проверка Tkinter открывает тестовое окно: закройте его перед запуском.
Генератор создаёт учебные папки `minimal`, `files` и `deep` в `.generated/`.
Последняя команда открывает GUI с загруженной папкой `deep`.
Команды эмулятора вводятся в нижнюю строку окна с нажатием Enter.
Без источника VFS: `python3 -m src.main`. Через файл запуска:
`sh run.sh --vfs .generated/deep`.

На Windows:

```bat
python -m src.fixtures
run.bat --vfs .generated/deep
```

## Этап 1. REPL

Заголовок окна: `Эмулятор - [username@hostname]`. Имена пользователя
и компьютера берутся из ОС. REPL читает строку, выполняет команду
и выводит результат. Парсер разделяет ввод по пробелам; кавычки
не объединяют слова. Пути с пробелами в командах не поддерживаются.
В первом этапе `ls` и `cd` были заглушками. С четвёртого этапа они
показывают файлы и меняют виртуальный текущий каталог.
Неизвестная команда и неверные аргументы выводят `error:`.
`exit` без аргументов закрывает окно.

## Этап 2. Конфигурация

- `--vfs PATH` - папка-источник VFS.
- `--script PATH` - файл UTF-8 с командами эмулятора.
- `--batch` - выполнить скрипт без интерактивного окна.
- `--help` - справка по параметрам.

Относительные пути запуска отсчитываются от рабочей папки процесса.
При запуске выводится `configuration` с итоговыми параметрами.
В стартовом скрипте поддерживаются комментарии с `#` вне кавычек,
в том числе после команды. На экране видны ввод и вывод.
Ошибка содержит номер строки. Следующие команды продолжают выполняться;
`exit` прекращает скрипт.

```sh
sh run.sh --vfs .generated/deep --script examples/stage4.txt --batch
```

Коды завершения: 0 - успех, 1 - ошибка загрузки или скрипта,
2 - ошибка параметров запуска.

## Этап 3. VFS

Источник - каталог на диске. При запуске структура и байты файлов
считываются в память в словарь виртуальных узлов. Без `--vfs` создаётся
пустой корень `/`. Ссылки и специальные файлы не загружаются.

- `vfs-info` - имя системы и SHA-256 структуры, содержимого и виртуальных
  метаданных: прав, владельцев и групп.
- `vfs-init` - сброс VFS до пустого корня и очистка физического источника.
  Это предусмотренное заданием исключение из работы только в памяти.

Для сброса используйте учебную папку `.generated/deep`.
Корень диска, домашняя папка, текущая папка проекта и её предки защищены.
Восстановление файлов: `python3 -m src.fixtures`.
Генератор создаёт пустую систему, систему с несколькими файлами и систему
с вложенностью не менее трёх уровней. Учебные данные исключены из Git.

## Этап 4. Основные команды

| Команда | Поведение |
|---|---|
| `ls [path]` | Содержимое каталога или имя указанного файла |
| `ls -a [path]` | Включает скрытые имена |
| `ls -l [path]` | Тип, права, владелец, группа, размер в байтах, имя |
| `ls -al [path]` | Оба режима одновременно |
| `cd [path]` | Переход в каталог; без аргумента - в `/` |
| `tail [-n count] file` | Последние 10 строк или заданное число строк |
| `who` | Имя реального пользователя текущего сеанса эмулятора |
| `wc [-l\|-w\|-c] file` | Число переводов строки, слов и байтов |

Пути относятся к VFS. Поддерживаются абсолютные и относительные пути,
`.` и `..`. Выход выше корня оставляет путь `/`.
`ls -l` показывает виртуальные метаданные в упрощённом формате.
`who` показывает текущий сеанс эмулятора, без других сеансов ОС.
`tail` читает текст UTF-8. При `-n 0` выводит пустую строку;
отрицательное и нечисловое количество строк вызывают ошибку.
`wc` без флага выводит три числа: строки, слова, байты.
`wc -c` считает байты, а не символы, и работает с двоичными файлами.
Строки считаются по переводам строки: последняя строка без перевода
строки не увеличивает этот счётчик.

## Пример проверки в окне

После запуска с `.generated/deep`:

```text
ls -a
cd /docs/notes/deep
ls
tail -n 2 info.txt
wc info.txt
cd ..
cd
who
cd /missing
wc /docs
vfs-info
exit
```

Для `info.txt` команда `tail -n 2` выводит `second line` и `third line`,
а `wc` выводит `3 6 34 info.txt`. Ошибки не закрывают окно.

## Тесты и сценарии

```sh
python3 -m unittest discover -s tests -v
sh scripts/stage2.sh
sh scripts/stage3.sh
sh scripts/stage4.sh
```

Сценарий этапа 3 очищает учебные данные через `vfs-init`.
Сценарий этапа 4 создаёт их заново и проверяет команды и ошибки.
Подробные сценарии: `examples/stage4.txt`, `examples/stage4-errors.txt`.

## Структура проекта

- `src/main.py` - запуск и создание сеанса.
- `src/interface.py` - окно, строка ввода и вывод.
- `src/shell.py`, `src/parsing.py` - выполнение и разбор команды.
- `src/config.py`, `src/startup.py` - параметры и стартовый скрипт.
- `src/vfs.py`, `src/loaders.py` - данные в памяти и загрузка папки.
- `src/services.py` - информация и сброс VFS.
- `src/base_commands.py` - команды четвёртого этапа.
- `src/fixtures.py` - генератор учебных папок.
- `src/settings.py` - настройки варианта.
- `tests/`, `examples/`, `scripts/` - проверки и демонстрация.
- `docs/` - описание функций и инструкции.

В `Makefile` есть цели `run`, `fixtures` и `test`.
Каждый этап сохраняется отдельным коммитом.
Предыдущие версии доступны в истории
[репозитория](https://github.com/aniantm05-hash/configuration-management-variant14).
